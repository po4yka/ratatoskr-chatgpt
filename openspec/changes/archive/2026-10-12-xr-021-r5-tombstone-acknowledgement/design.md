## Decisions

- Acknowledgement state lives on the outbox row. The tombstone envelope's `event_id` is the identity Knowledge echoes as `acknowledged_event_id`, so the update matches `payload->>'event_id'` and `payload->>'tenant_id'` (the envelope tenant is the owner). A partial expression index keeps the lookup off a table scan.
- The same pump pass handles first publication and resend. A single query returns unpublished rows due for a first attempt and published, unacknowledged tombstones due for a resend; a resend row is published exactly like any other (same bytes, same `Nats-Msg-Id`) and then rescheduled instead of marked published again. The broker collapses a repeated id inside the events stream's 120 second duplicate window, so the 600 second default is deliberate and the library accepts any value so a test can use a short window on its own stream.
- Resend policy is a plain value (`TombstoneResend { after, cap }`) passed to the pump with a builder. Its defaults are constants shared with the configuration loader so there is one number.
- The acknowledgement also sets `published_at` when it is still null, so an acknowledged row is not published a second time after a crash between the PubAck and `mark_published`.
- The consumer lives in the library crate beside the pump because it needs the same connection options (service nkey and the `_INBOX_chatgpt` prefix the ACL demands). It verifies the durable (filter, explicit ack, 30 s ack wait) and never creates it. The service supervises it: a task that returns before shutdown flips bus readiness false and the process exits non-zero (S02 rule 5).
- Gauges are refreshed once per pump pass from one aggregate query. They are not readiness inputs: a Knowledge outage must not make the producer unready.
