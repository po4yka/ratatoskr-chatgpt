## Decisions

- The row is the unit of serialization. The batch is still chosen without a lock; the lock is taken per row, with `for update skip locked`, in a transaction that also publishes and marks. The pump never waits on a lock, so it cannot take part in a deadlock. A deletion's `DELETE ... RETURNING` waits for the pump and, under READ COMMITTED, deletes the committed version of the row, so `RETURNING` carries the sequences the pump just wrote. If a test shows that this does not hold on the installed PostgreSQL, a `FOR UPDATE` selection ahead of the delete is the fallback.
- The transaction holds one pool connection while a publish is in flight. The hold is bounded by the JetStream request timeout, which the pump sets explicitly to 5 s (`PUBLISH_TIMEOUT`), because the default is a library detail that would silently change the lock bound.
- The resend path of an already published tombstone and `mark_undeliverable` keep their own short statements and take no lock: they record no sequence.
- `mark_published` merges the existing array, the carried sequences and the new one with `array(select distinct ... order by)`, so the array is ascending and a duplicate PubAck adds nothing. `rows_affected` must be exactly 1; anything else is `MarkLost`, counted, and the acknowledged sequence is carried so it is not lost.
- The carry map is `Arc<std::sync::Mutex<HashMap<i64, Carried>>>` on `ArchiveEventOutbox`, never held across an await. Only the seven content-bearing fact types are carried: an operation report, a tombstone and an erasure command are never erased from the stream, so a sequence of theirs would only make Edge count `refused`. The entry is dropped when the row is marked published or its command is enqueued.
- The command builder is extracted from `privacy_deletion/erasure.rs` into `stream_erasure.rs`, used by the deletion and by the pump. The deletion's deduplication key stays `stream-erasure:<request>:<owner>:<index>`; the pump's is `stream-erasure:reconcile:<event id>:<index>`, so a second pass enqueues nothing more. The pump-originated `request_ref` names no real deletion request and `DEVELOPMENT.md` says so.
- `PublishProbe` copies `EraseGate`: an `Arc` with `reached()` and `resume()`, set only by tests. Pauses fire once so a later pass is not held.
- Residual, documented and not hidden: the process crash between the PubAck and the commit loses the in-memory carry. A restart inside the 120 s duplicate window is harmless (the republish is a duplicate with the original sequence); after it the republished copy is new and the first copy is not named by any record.
